## Plan: StoryScript Fluent Localization

### TL;DR
Add story-content localization to the StoryScript toolchain while leaving application-shell localization with the host. StoryScript gains ID-only keyed text literals for narration, dialogue, and choice labels; strict English and Indonesian Fluent catalogs; BCP-47 locale negotiation; signed canonical catalog entries in StoryBundle; locale-neutral message references and argument snapshots in saves/history; project-aware source playback; locale-aware bundle playback; catalog CLI workflows; and workspace-aware VS Code intelligence. Flutter continues to render resolved story text but uses `gen_l10n` for its own menus, actions, errors, and accessibility labels. This deliberately rewrites the current StoryBundle v1 and StoryPlayer save v1 contracts in place: compiler/runtime identities, descriptor hashes, generated bindings, fixtures, and documentation move together, and old bundles/saves are rejected without migration.

### Implementation Steps

#### Phase 1: Contract and Schema Foundation — freeze the rewritten v1 localization, bundle, and save boundaries
- Update `PLAN.md` with the language-level distinction between ordinary quoted text and the dedicated prefixed-string keyed literal `@"fluent-message-id"`, whose sole value is a native Fluent message identifier. Limit keyed text to narration, dialogue bodies, and choice labels; explicitly exclude actor/project display names, scene/actor IDs, asset paths, diagnostics, expressions, and stored string data.
- Rewrite `bundle/proto/storybundle/v1/compiled_story.proto` so each player-facing text site is an explicit plain-text-or-message-reference union. A message reference carries its stable ID and ordered typed argument contract, while project localization metadata records the canonical default locale and complete supported-locale set. Do not embed every catalog in `CompiledStory`.
- Rewrite `player/proto/storyplayer/v1/player_save.proto` so current, pending, choice, and history text can be plain text or a locale-neutral message reference with ordered exact scalar argument snapshots. Preserve exact `i64` and decimal wire values; do not persist rendered localized strings for keyed content or bind saves to one locale.
- Define the signed catalog-entry contract in `docs/contracts/storyscript_localization_v1.md` and update both existing v1 contracts. Catalog entries are canonical semantic FTL with author comments and host paths removed, keyed by canonical BCP-47 locale, indexed by the signed manifest, bounded independently, and unavailable before complete bundle verification.
- Keep the archive-wide 100 MiB and per-entry 64 MiB ceilings; add explicit localization ceilings of 64 declared locales, 100,000 message IDs, 16 MiB per canonical catalog, 256 UTF-8 bytes per message ID, and the existing 1 MiB rendered-event cap. Locale count/catalog totals remain subject to the stricter existing archive and entry limits.
- Pin `fluent` 0.17.0 and the required Fluent syntax/language-ID crates through the owning Cargo locks. Define the supported Fluent profile: messages, terms, variable references, select/plural expressions, and safe number formatting; reject unsupported custom functions, datetime formatting, cyclic references, attributes not represented by StoryScript, and any construct that cannot be validated or bounded deterministically.
- Update `bundle/rust/tests/contract_v1.rs` and `player/tests/save_contract.rs` before dependent implementation: descriptor hashes, locale metadata, plain-versus-keyed text, typed arguments, signed catalog entry type, no rendered keyed save text, no maps, hard limits, and deliberate incompatibility with prior descriptors.
- Regenerate canonical Rust/Dart Protobuf outputs and pinned schema hashes, but do not change runtime behavior yet beyond keeping legacy plain-text paths compilable.
- **Checkpoint**: Both rewritten v1 schemas compile, generated contracts and hashes are pinned, localization limits and compatibility rejection are normative, and legacy plain-text runtime code still compiles against the new unions. Safe to stop here — all later modules target one stable contract and no partially trusted catalog is exposed.
- **Checkpoint Verification**: Run `cargo test --manifest-path bundle/rust/Cargo.toml --test contract_v1 && cargo test --manifest-path player/Cargo.toml --no-default-features --test save_contract && cargo run --manifest-path bundle/rust/Cargo.toml -- schema check`.

- Enforce native Fluent identifier syntax and one declaration per message ID across the merged root/include project. Duplicate IDs, empty/invalid IDs, keyed text in excluded contexts, and ordinary interpolation syntax inside an ID are compile-time errors with stable diagnostics.

When a raw session has keyed text but no project/catalog context, emit the stable message ID as visible text exactly as aligned; expose/document the unresolved-localization status rather than pretending a locale was selected.

#### Phase 3: Project Catalogs and Author CLI — make complete Fluent catalogs a strict build input

- Add a bounded localization project module under `bundle/rust/src/` that parses FTL, builds a transitive message/term dependency graph, rejects syntax errors/cycles/unsupported constructs, extracts variable references, and validates every source ID against every declared locale.
- Require strict coverage for export/check: every keyed source ID exists exactly once in every declared catalog; every catalog entry is used; and each locale has the same transitive argument-name set. Resolve each argument name against the message site's visible StoryScript variables and record its immutable StoryScript type. Reject arrays; allow strings and booleans; allow integers/decimals only under the runtime exactness guard defined in Phase 5.
- Add `storyscript-bundle localize extract`, `localize sync`, and `localize check` workflows in `bundle/rust/src/cli.rs`. Extraction emits a deterministic ID inventory with source context; sync adds missing stubs without deleting translator content and reports obsolete/conflicting entries; check is non-mutating and is the release gate. Machine-readable diagnostics must include project-relative source/catalog locations without leaking host absolute paths.
- Update project initialization in `bundle/rust/src/cli.rs` to scaffold an optional localized project with the localization config and default catalog when requested, while preserving the existing minimal non-localized initializer.
- Extend `bundle/rust/tests/project_compile.rs`, `ir_conversion.rs`, `cli_init.rs`, and `cli_export.rs` for English/Indonesian strict coverage, plural/select patterns, terms, missing/unused/duplicate IDs, argument drift, out-of-scope locals, arrays, unsafe functions, canonical locale/path collisions, deterministic extract/sync/check output, and non-localized project compatibility.

#### Phase 5: Rust Locale Runtime and Save Semantics — render one immutable session locale without losing exact progress
- Add an execution-owned localization module under `player/src/` that negotiates ordered requested BCP-47 tags by exact match, configured language-only match, then project default; returns the resolved locale; constructs a bounded Fluent bundle from already validated project/verified resources; and never fetches translations over the network.
- Refactor `player/src/model/`, `contract.rs`, `engine.rs`, `history.rs`, and `runtime.rs` so keyed narration/dialogue/choices carry message ID plus an ordered immutable argument snapshot. Snapshot values when an event is flattened so later variable mutation cannot rewrite pending/current/history text. Keep actor names, media, scene labels, standalone variable output, structured errors, and legacy plain text non-localized.
- Map string arguments as opaque text and booleans as stable selector values. Convert integers/decimals to Fluent numbers only when the value round-trips exactly through the crate's `f64` representation; otherwise fail the interaction transactionally with a structured localization-number error. Arrays are rejected at project validation and hostile restore validation.
- Apply Fluent's variable isolation behavior, reject resolver errors instead of returning partial patterns, count formatting work against interaction limits, and enforce the existing 1 MiB rendered-event cap after formatting. ### Architectural Decisions & Scope Boundaries
- **In-Scope**: ID-only keyed narration/dialogue/choice literals; legacy plain text; strict complete Fluent English/Indonesian catalogs; BCP-47 negotiation; signed canonical catalog entries; rewritten StoryBundle/save v1 contracts; immutable session locale; exact scalar argument snapshots; project-aware source and verified-bundle APIs; raw ID display; extract/sync/check CLI; full i18n-specific VS Code workspace intelligence; Flutter `gen_l10n` shell localization; atomic save/restore locale switching in Station Nine; focused tests, CI, and complete docs.
- **Explicitly Excluded**: Localization of actor/project display names, scene/actor IDs, media paths, runtime diagnostics, string-variable data, arbitrary expressions, standalone variable output, or assets; live mutation of an existing player locale; partial shipping catalogs; remote translation download; translator web UI; dynamic catalog hot reload in production; old-v1 bundle/save migration; persistent app locale storage; cloud sync; rich text/HTML/Markdown interpretation; registry publication. Implementing-agent Docker/Compose changes or commands, local Supabase operations, and Flutter UI/widget/golden/integration test creation/modification/execution are always excluded and human-owned.
- **Assumptions**: Message IDs are globally unique across a compiled root/include project and use native Fluent identifier rules. Every localized project ships a complete default catalog. Locale tags are canonical BCP-47 values. Session locale is selected only at open/restore. Raw keyed playback intentionally displays IDs. Story variable state remains locale-neutral; message arguments are snapshots. Fluent numbers are accepted only when exactly round-trippable. Catalog content is trusted only after the existing bundle signature pipeline. Rewriting v1 is acceptable because the project is pre-1.0 and exact identity/no migration are already documented.
- **Impacted Modules & Ownership**: Rust language/toolchain (`parser/rust/`, `bundle/rust/`, `bundle/proto/`); Rust runtime/save (`player/`, `player/proto/`); source Flutter package (`storyscript_player_core/`); StoryBundle Flutter package/example (`storyscript_bundle/`); editor (`tool/vscode-storyscript/`); shared CI/docs (`.github/`, `docs/`, `PLAN.md`, `README.md`). ### Risk & Security Assessment
- **Identified Risks**:
  - `[HIGH]` — **Catalog Trust Bypass or Archive Injection**: Locale paths/entries could traverse, collide, remain unsigned, or be parsed before verification. **Mitigation**: Fixed sandboxed paths, canonical BCP-47 names, NFC/case collision checks, distinct manifest entry types, complete digest/signature coverage, no extraction, bounded reads, and no model/player/catalog exposure before strict verification.
  - `[HIGH]` — **Hostile Save Message Confusion**: Forged IDs, argument types, targets, or oversized values could select unintended messages, exhaust formatting, or corrupt history. **Mitigation**: Canonical decode, exact model ID/argument validation, scalar/type/size/count checks, cycle checks, candidate-only restore, rendered-output cap, and atomic publication.
  - `[HIGH]` — **Silent Numeric Precision Loss**: Fluent's `f64` number representation can alter StoryScript `i64`/decimal values and choose the wrong plural. **Mitigation**: Exact round-trip guard, structured compile/runtime diagnostics, transactional rollback, test boundary values, and prohibit lossy fallback.
  - `[HIGH]` — **Catalog/Source Drift**: Missing IDs or divergent variables could expose IDs, fail at runtime, or use stale values. **Mitigation**: Globally unique IDs, complete strict catalogs, same transitive argument set/types for every locale, non-mutating release check, signed compiled contracts, LSP diagnostics, and runtime fail-closed validation.
  - `[HIGH]` — **Breaking v1 Replacement**: Existing signed bundles and saves become unreadable. **Mitigation**: Deliberate compiler/runtime/hash bump, explicit incompatibility errors, rebuild every fixture/release artifact, no false migration promise, coordinated rollout/rollback playbook, and preserve matching old binaries externally if recovery is required.
  - `[MEDIUM]` — **Formatting Expansion or Cycles**: Message/term references and selects can amplify work or recurse. **Mitigation**: Compile-time dependency graph/cycle rejection, locale/message/catalog limits, interaction operation budget, 1 MiB output cap, no custom functions, and bounded formatter errors.
  - `[MEDIUM]` — **Bidi/Unicode Spoofing**: Translator content or interpolated user text could confuse visual order or imitate controls. **Mitigation**: Preserve Fluent FSI/PDI isolation, render plain text only, retain semantic labels/non-color cues, normalize identifiers/paths but not natural-language prose, review catalog changes as trusted content, and test screen readers.
  - `[MEDIUM]` — **Workspace Rename Corruption**: Cross-file editor edits could overwrite translator changes or touch the wrong project. **Mitigation**: Project-root scoping, Fluent AST ranges, unique source IDs, versioned open-document checks, atomic previewable `WorkspaceEdit`, no regex replacement, no deletion during sync, and fixture tests.
  - `[MEDIUM]` — **Raw ID Leakage to End Users**: A host may accidentally use raw APIs for a localized script. **Mitigation**: Explicit unresolved-localization metadata, documentation/warnings, project APIs in examples, distinctive diagnostics, and tests; retain ID display only because it is an aligned compatibility decision.
  - `[LOW]` — **Story Structure Disclosure**: Stable IDs and catalog text expose semantic structure. **Mitigation**: Reiterate that StoryBundle is not DRM/encryption, avoid secrets/PII in IDs, and do not log IDs with argument values by default.
- **Data Sensitivity**: Message argument snapshots and existing variables may contain player names or other PII. Saves remain unencrypted and unauthenticated; hosts own encryption, retention, deletion, backup, cloud authorization, and GDPR/data-residency policy. Catalogs and rendered story text are recoverable from bundles. Logs must omit raw saves, catalog argument values, and user-provided strings unless an approved secure diagnostic flow exists.
- **Dependency & Supply-Chain Risks**: Pin and lock Rust `fluent` 0.17.0, `fluent-syntax` 0.12.0, the selected `unic-langid`/Fluent transitive line, and npm `@fluent/syntax`; review Apache-2.0/MIT compatibility with LGPL-2.1; run Cargo audit/deny and npm audit/lockfile review; keep custom functions disabled; and require generated/lockfile diffs in CI. No network catalog dependency is introduced at runtime.
- **AuthN / AuthZ Gaps**: No user authentication or remote authorization surface is added. The relevant authorization boundary is bundle trust: host-provided Ed25519 keys and strict verification must cover catalogs before playback. Explicit unsigned development remains conspicuous and must never become a fallback after signature/catalog failure. Source-project catalogs are local developer inputs and are not treated as authenticated distribution artifacts.
- **SQL Schema Audit**: Not applicable — discovery found no SQL query, RPC, database scan destination, or data-access boundary in scope, so there is no legacy `SELECT` nullability mapping to audit.
